# Граф производства — сервер

API для клиента `PePorMAty/gpt-graph-client`: строит шаги цепочек с
моделями (Qwen/DeepSeek через DashScope или OpenAI), хранит графы, ищет
источники, сверяет продукты со справочниками ОКПД2/ТН ВЭД/ГИСП.
Node.js, Express 5, CommonJS.

## Владелец и порядок работы
- Общаемся по-русски, дружелюбно, с объяснением, что и зачем делаем.
- **Ничего не мержить без подтверждения владельца.** PR — только по просьбе.
- Ветки (с 2026-11-09): `develop` — то, что на боевом сервере. Работа идёт
  в своей ветке от `develop`; владелец сливает её в `develop` и выкладывает.
  В `develop` пушить нельзя. Прежние общие ветки (`claude/combined-testing`,
  `claude/cloud-product-testing-cg98tm`, `claude/beautiful-hamilton-4whfax`)
  в него влиты; `main` — старая, не трогать.
- Боевой сервер — https://sorangptgraph.xyz/api (pm2 за nginx), выкладывает
  владелец: `git checkout develop && git pull && pm2 restart all`.
  `ecosystem.config.js` — шаблон pm2, не настоящая конфигурация.

## Запуск и проверки
- `node server.js` (порт `PORT`, по умолчанию 3001; проверка — `/api/health`).
  Ключи моделей и подключение к Postgres — в `.env` (в git не попадает).
- `npm test` — тесты разбора шага на подставных ответах модели
  (`test/`, node:test). Тесты хранилища графов на PostgreSQL — с
  `TEST_DATABASE_URL` (тестовая база, не боевая: тесты чистят `app.*`); без
  неё — только на файлах. Линтера нет; минимум для остального — модуль
  загружается: `node -e "require('./routes/step/build.js')"`.
- Промпты обобщения и разбор шага проверяй скиллом `prompt-check`
  (`.claude/skills/prompt-check/`): `--dry` бесплатно, живой прогон — по
  запросу к модели на кейс.
- Свою проверку без модели делай так же, как в `test/`: заглушка в
  `require.cache` для `routes/sources/utils` (там `callOpenAIResponsesRaw`)
  и вызов обработчика роутера напрямую.
- Запросы к живой модели стоят денег — только когда владелец просит или
  без этого не проверить промпт; говори, сколько запросов ушло.

## Карта кода
- `server.js` — монтирование роутеров: `/api/graphs/...` (модель),
  `/api/graph-files/...` (сохранённые графы), `/api/...` (справочники,
  источники из базы).
- `routes/step/` — пошаговое построение: `sources.js` (поиск источников;
  найденное проверяет `utils/verifySources.js`, научные ссылки — сверкой с
  Crossref `utils/crossref.js`: модель выдумывает DOI и номера статей),
  `aggregate.js` (обобщение; промежуточные продукты разделов базы — строкой
  в блоке, дозапрос при перепрыгивании уровня — `utils/levelSkip.js`, при
  выходе-не-продукте: класс веществ, смесь одной строкой, переработка
  отходов — `utils/outputCheck.js`),
  `build.js` (разбор шага в узлы + страховки по тексту обобщения),
  `check.js` (проверка шага моделью без поиска: верно ли «сырьё → продукты»,
  исправление — переименованиями; зовут превью шага и отказ баланса,
  `utils/stepCheck.js`), промпты — `routes/step/utils/prompts.js`.
  Действуют прежние промпты (с 2026-11-18, решение владельца). Промпты v4
  (владелец, 2026-11-17) — дословно в `routes/step/prompts-v4/`, одобренные
  правки помечены «(ПРАВКА дата)» и перечислены в README там же; включаются
  без git — `STEP_PROMPTS=v4` в `.env` и `pm2 restart all`; строки поиска в
  блоках обобщения v4 (`utils/searchHints.js`) выключает
  `STEP_SEARCH_HINTS=off`.
- `routes/sources/utils/openai.js` — единый транспорт к моделям (`MODELS.md`).
- `routes/graph-files/` — библиотека графов и данные рядом с ними (закладки,
  история, расчёты баланса, идентификаторы), снимки «Поделиться», шаблон
  промпта — через хранилище `routes/graph-files/store/`: файлы
  `data/<вид>/<граф>.json` (по умолчанию) или PostgreSQL (`GRAPH_STORE=pg`,
  схема `app`). `data/` не в git.
- `db/` — PostgreSQL: подключение (`pool.js`, те же `DB_*`), миграции
  `db/migrations/NNN_*.sql` (`npm run pg:migrate`), перенос библиотеки
  файлы ⇄ база (`graphTransfer.js`, `scripts/migrate-graphs-to-pg.js`,
  `scripts/export-graphs-from-pg.js`).
- `routes/industry/` — справочники и идентификация продуктов
  (`IDENTIFICATION.md`); коды ОКПД2/ТН ВЭД моделью по файлам `reference/`
  — `codes.js` (`/graphs/gpt/product-codes`, сохранённые — в
  `data/product-codes.json` и в ответе `/industry/lookup`);
  `routes/local-sources/` — документы в базе
  (`LOCAL-SOURCES.md`).
- `TODO.md` — отложенные договорённости с разбором; читай перед тем, как
  переделывать описанное там. Пункты «просил напоминать» (вверху файла) —
  напоминай владельцу, когда работа касается этих мест (промпты v4:
  изделия вверх — если вернёмся к v4).
- `PG-MIGRATION.md` — план перехода хранилищ (файлы графов, SQLite) на
  PostgreSQL по этапам (порядок владельца 18.11): графы → источники и
  балансы → слой знаний и векторы (GraphRAG) → чат с ИИ в открытом графе,
  в отдельном окне → пользователи (JWT, свои и общие графы, сокеты,
  комментарии). `node scripts/db-info.js` — что за Postgres на
  сервере (ничего не меняет).
- `BACKUP.md` — резервные копии (`npm run backup`, `scripts/backup.js`):
  `data/`, снимки SQLite, дамп Postgres и PDF — зашифрованными age в
  приватный репозиторий; на сервере — только внутри git (место на диске
  мало, есть запас 300 МБ). `data/gisp.sqlite` и выгрузка ГИСП
  `data/data-base/` не копируются — пересобираются.

## Как здесь пишут код
- Комментарии — по-русски; объясняют, почему так.
- Клиент на сайте может быть старее или новее сервера: новые поля ответа —
  необязательные, старые запросы должны работать как раньше.
