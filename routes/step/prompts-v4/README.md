# Промпты построения шага v4

Тексты владельца (2026-11-17) — дословно, по одному на файл:

| Файл | Где используется |
|---|---|
| `sources-up.txt`, `sources-down.txt` | поиск источников «из чего получают» / «что получают из продукта» (`routes/step/sources.js`): полный промпт — для OpenAI и запасного пути через chat; `{EXPAND_PRODUCT}`, `{ПРОДУКТ}`, `{N}` — строками параметров перед текстом (`prompts.js` → `v4SourcesPrompt`) |
| `aggregate-down-system.txt`, `aggregate-down-user.txt` | обобщение шага вниз (`routes/step/aggregate.js`) |
| `aggregate-up-system.txt`, `aggregate-up-user.txt` | обобщение шага вверх |

Поиск через Responses API Qwen берёт не полный промпт, а короткую задачу
`v4SearchBrief` (`routes/step/utils/prompts.js`): с ней модель ищет 3–4 раза
за минуту, а с полным текстом искала до 27 раз и 5 минут. Из v4 в неё
перенесено то, что нужно обобщению: маркер `search_product`, стадии
раздельно, строки `inputs_outputs_hint` в формате v4, роли, `industrial_status`.

Строки стадий и цитаты поиска идут в блок обобщения (с 2026-11-17,
`routes/step/utils/searchHints.js`) — после описания, до текста страницы,
сверх предела блока; у разделов базы — нет (их строки — сводка раздела).
Адрес и продукт поиска модель в строках не пишет — сервер дописывает их в
формате v4: ответ поиска на ~20–25 % короче. `STEP_SEARCH_HINTS=off` в `.env`
(и `pm2 restart all`) — блок без строк, как раньше.

Что сервер добавляет к текстам:
- в USER обобщения — черту «входные данные — не часть ответа» перед
  «# Родословная» (без неё модель переписывала данные в ответ); ответ
  сервер всё равно чистит от такого эха (`aggregate.js` → `withoutEcho`);
- `SOURCE_CURRENT_PRODUCT` — «не передан»: источники бывают взяты у предка,
  и сервер не знает, для какого продукта их искали.

## Правки владельца к текстам (2026-11-17)

По живым прогонам 2026-11-17 («Автомобиль» вверх, «Адипиновая кислота» →
«Нейлон 6,6» вниз) владелец одобрил правки; в файлах они помечены
«(ПРАВКА 2026-11-17)» — по этой метке их видно рядом с исходным текстом.

- **Альтернативы** (`aggregate-*-system.txt`): частичную альтернативу не
  отбрасывать, а помечать partial; каждый другой маршрут со своим продуктом —
  альтернатива, до 5. Было: «частичные альтернативы не превращай в
  продуктовые» — а частичным v4 считает почти всё, и полиолы с
  пластификаторами адипиновой кислоты пропали «ради краткости».
- **Достаточность complete** (`aggregate-*-system.txt`): прямой перечень
  входов и выходов в блоке или одинаковый состав в двух независимых блоках.
  Было — partial на всё, даже на нейлон 6,6 из адипиновой кислоты.
- **Шаблон альтернатив** (`aggregate-*-user.txt`): без условных слов «Если
  альтернатив нет… Иначе для каждой…» — модель переписывала их в ответ;
  правило — строкой в «Формате ответа».
- **`industrial_status`** (задача поиска `v4SearchBrief`, не файл здесь):
  страница продавца или перечень применений — unclear.

## Включение и откат

**С 2026-11-18 по решению владельца v4 выключены** — снова действуют прежние
промпты поиска и обобщения (`routes/step/utils/prompts.js`). Тексты v4 с
одобренными правками остаются здесь.

`STEP_PROMPTS=v4` в `.env` и `pm2 restart all` — включить v4 без git; убрать
переменную (или любое другое значение, например `legacy`) — снова прежние.
Какая версия действует, видно в ответе обобщения (`promptsVersion`) и в
`GET /gpt/step/sources/prompt` (`version`), там же при v4 — `sufficiency` из
«Достаточности данных».
