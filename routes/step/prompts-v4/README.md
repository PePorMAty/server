# Промпты построения шага v4

Тексты владельца (2026-11-17) — дословно, по одному на файл:

| Файл | Где используется |
|---|---|
| `sources-up.txt`, `sources-down.txt` | поиск источников «из чего получают» / «что получают из продукта» (`routes/step/sources.js`): полный промпт — для OpenAI и запасного пути через chat; `{EXPAND_PRODUCT}`, `{ПРОДУКТ}`, `{N}` — строками параметров перед текстом (`prompts.js` → `v4SourcesPrompt`) |
| `aggregate-down-system.txt`, `aggregate-down-user.txt` | обобщение шага вниз (`routes/step/aggregate.js`) |
| `aggregate-up-system.txt`, `aggregate-up-user.txt` | обобщение шага вверх |

Поиск через Responses API Qwen берёт не полный промпт, а короткую задачу
`v4SearchBrief` (`routes/step/utils/prompts.js`): с ней модель ищет 3–4 раза
за минуту, а с полным текстом искала до 27 раз и 5 минут. Из v4 в неё
перенесено то, что нужно обобщению: маркер `search_product`, стадии
раздельно, строки `inputs_outputs_hint` в формате v4, роли, `industrial_status`.

Что сервер добавляет к текстам:
- в USER обобщения — черту «входные данные — не часть ответа» перед
  «# Родословная» (без неё модель переписывала данные в ответ); ответ
  сервер всё равно чистит от такого эха (`aggregate.js` → `withoutEcho`);
- `SOURCE_CURRENT_PRODUCT` — «не передан»: источники бывают взяты у предка,
  и сервер не знает, для какого продукта их искали.

## Откат

`STEP_PROMPTS=legacy` в `.env` и `pm2 restart all` — прежние промпты поиска
и обобщения целиком, без git. Убрать переменную (или любое другое значение) —
снова v4. Какая версия действует, видно в ответе обобщения
(`promptsVersion`), там же — `sufficiency` из «Достаточности данных» v4.
