# Справочники

Файлы, которыми размечаются продукты графа: классификаторы кодов и справочник
синонимов веществ. Лежат в репозитории, а не в `data/`, намеренно: меняются
редко, правятся человеком и должны быть одинаковыми на всех машинах. С
`git pull` они приезжают сами.

Здесь описано, **что лежит в каждом файле**. Как это работает вместе — от
выгрузки ГИСП до узла на полотне — в `../IDENTIFICATION.md`.

Выгрузка классификаторов: 24 июля 2025.

| Файл | Что внутри |
|---|---|
| `okpd2.txt` | классификатор продукции: код → наименование |
| `okpd2-retired.txt` | коды, исчезнувшие из свежего классификатора |
| `tnved.txt` | товарная номенклатура ЕАЭС, иерархическая |
| `synonyms.txt` | справочник веществ, ведётся руками |
| `synonyms-wikidata.txt` | то же, собрано скриптом из Wikidata |
| `synonyms-stop.txt` | что из собранного машиной не брать |

## okpd2.txt — 1 736 позиций, 252 КБ

Общероссийский классификатор продукции по видам экономической деятельности.
Формат простой: `код⇥наименование`, по строке на позицию.

```
20.16.10	Полимеры этилена в первичных формах
```

Коды шестизначные (`NN.NN.NN`). В реестре ГИСП они длиннее — `20.16.10.110`, —
поэтому сопоставляются по первым восьми символам.

**ОКПД2 классифицирует группы продукции, а не вещества.** Присваивать код узлу
графа по названию нельзя: «Этилен» по словам уверенно ложится на «Полимеры
этилена», то есть на полиэтилен. Справочник годится для расшифровки кода,
пришедшего из реестра, — и только.

## tnved.txt — 13 044 кода, 1,6 МБ

Товарная номенклатура внешнеэкономической деятельности ЕАЭС. Файл
иерархический, и разбирать его сложнее:

```
РАЗДЕЛ VI
ГРУППА 29 ОРГАНИЧЕСКИЕ ХИМИЧЕСКИЕ СОЕДИНЕНИЯ

2901	Углеводороды ациклические:
2901 21 000	– – этилен	–
```

- строки без табуляции — заголовки разделов и групп;
- у строк с табуляцией три поля: код, наименование, единица измерения;
- код бывает пустым — это заголовок уровня, а не позиция;
- глубина вложенности показана количеством тире в начале наименования, до
  десяти уровней. Без родителей дочерние строки бессмысленны: «– – – прочие»
  сам по себе ничего не значит, полное имя собирается по цепочке вверх;
- десятка четыре строк — примечания, у них в колонке кода лежит текст. Годными
  считаются только строки, где код состоит из 4–10 цифр.

В отличие от ОКПД2, здесь названия — **сами вещества**, теми же словами, что и
в графах: этилен, пропилен, бензол, толуол. На двадцати продуктах реального
графа ТН ВЭД нашёл 19, ОКПД2 — 9, причём половину неверно.

## okpd2-retired.txt — коды, исчезнувшие из классификатора

Выгрузка ГИСП несёт код, присвоенный записи **при регистрации**, а
классификатор с тех пор менялся: `20.15.31.000` (мочевина), `20.13.63.000`
(пероксид водорода) исключены изменением №133/2026. Колонки со статусом в
плоском `okpd2.txt` нет, поэтому список собирается **разностью версий**:
коды, которые есть у нас и отсутствуют в свежем классификаторе.

```
node scripts/okpd2-refresh.js ОКПД.xlsx             # показать, что даст
node scripts/okpd2-refresh.js ОКПД.xlsx --retired   # переписать этот файл
node scripts/okpd2-refresh.js ОКПД.xlsx --names     # переписать okpd2.txt
```

Свежий классификатор — позиционный аргумент; `--names` и `--retired` значения
не принимают, пишутся всегда свои файлы. (Раньше путь задавался вслед за
ключом, и `--names --retired` кончалось тем, что первый ключ проглатывал
второй как своё значение.)

Сравнивается не с нашим файлом, а с кодами, которые реально встречаются в
реестре: снятым считается код, который в ГИСП есть, а в свежем классификаторе
отсутствует. Обратное направление не трогаем — коды, которых нет у нас, а в
свежем есть, это просто новые.

## synonyms.txt — справочник веществ, ведётся руками

Строка на вещество. Первое имя — **канон**, он же идентификатор продукта на
графе; дальше написания; в комментарии номер CAS.

```
Изопропилбензол | Кумол | ИПБ | Cumene   # CAS 98-82-8
```

Делает две работы: опознаёт узел (`identify`) и расширяет поиск по реестру
(ищем всеми написаниями сразу).

**Звёздочка = «только для опознания».** Написание, помеченное `*`, опознаёт
узел и участвует в слиянии, но по реестру не ищется:

```
Диэтиленгликоль | *ДЭГ   # CAS 111-46-6
```

Нужно там, где сокращение в реестре означает что-то другое: ДЭГ-1 — марка
эпоксидной смолы, R22 — типоразмер шины, СКД — марка активного угля.
Кандидатов показывает `node scripts/audit-products.js --abbr`.

**Осторожно при пополнении.** Ошибочный синоним молча сливает два разных
вещества в один узел графа, и заметить это потом нечем. Класть в одну строку
можно только то, что действительно одно вещество; «Гликоль» для этиленгликоля
или «Раундап» для глифосата — не синонимы, а класс и торговая марка.

## synonyms-wikidata.txt — то же, собрано машиной

```
node scripts/fetch-wikidata-synonyms.js --dry-run   # посмотреть, что выйдет
node scripts/fetch-wikidata-synonyms.js             # записать файл
```

Скрипт спрашивает Wikidata про названия, которые реально стоят на
сохранённых графах, и берёт номер CAS (свойство `P231`) вместе с русскими
синонимами. Файл **перезаписывается целиком** — править его руками
бессмысленно, правки уедут при следующем прогоне. Всё, что решено вручную,
место имеет в `synonyms.txt` и `synonyms-stop.txt`.

Строка отсюда, описывающая уже известное вещество, вливается в запись из
`synonyms.txt`: главным именем остаётся то, что выбрал человек.

## synonyms-stop.txt — чему из собранного не верить

Применяется **при чтении** и только к файлам, собранным машиной;
`synonyms.txt` стоп-лист не трогает — что человек написал, то и берём.

По строке на выброшенное написание. Годится, когда Wikidata называет
синонимом:

- книжную архаику — «Фениловый водород» для бензола;
- класс веществ вместо вещества — «Гликоль», «Витамины»;
- торговую марку — «Раундап» для глифосата;
- просто чужое вещество — «Полихлоропрен» приписался к изопрену.

Пометить целую строку (`whole`) или одно написание — решает сам стоп-лист:
совпало с каноном — уходит строка, совпало с написанием — только оно.

## Кодировка

Все файлы в UTF-8, но начало у них разное — проверено побайтно:

| Файл | BOM |
|---|---|
| `tnved.txt` | **есть** (`EF BB BF`), пришёл таким из выгрузки |
| `okpd2.txt` | нет (в выгрузке был; где потерялся — не установлено) |
| `okpd2-retired.txt`, все `synonyms*.txt` | нет |

Читать всё равно надо со снятием BOM (`utf-8-sig` или
`replace(/^﻿/, "")`): следующая выгрузка ТН ВЭД может прийти с ним
снова. Пересохранять файлы ради единообразия не нужно.
