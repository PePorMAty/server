# Модели: как сервер с ними разговаривает

Все запросы к моделям идут через один транспорт —
`routes/sources/utils/openai.js`. Провайдера (`openai` или `qwen`, то есть
DashScope с моделями Qwen и DeepSeek) и модель выбирает интерфейс.

## Что сервер делает сам (DashScope)

**Размышления выключены.** Новые Qwen и DeepSeek по умолчанию «думают» перед
ответом. Нашим задачам (найти источники, заполнить карточку, собрать шаг)
это вредит: запрос идёт минутами, размышления съедают лимит длины ответа, а
схему ответа (`json_schema`) в режиме размышлений модели держат плохо — отсюда
«ответ не по схеме». Поэтому в каждый запрос уходит `enable_thinking: false`.

**Поиск в интернете — всегда и глубокий.** При поиске источников уходят
`forced_search: true` (иначе модель порой отвечает по памяти одним-двумя
источниками) и `search_strategy: "max"` (больше страниц, чем у `turbo`).

**Схема ответа — ещё и текстом в промпте.** Модель, которая схему не держит,
видит её в системном сообщении и отвечает по ней, а не как попало.

**Поправки на модель.** Если модель отвергла параметр (ошибка 400), транспорт
читает текст отказа, убирает или меняет именно этот параметр и повторяет:

| Отказ модели | Что делает транспорт |
|---|---|
| не выключает размышления | отпускает думать, но с бюджетом 4000 токенов и таким же прибавком к лимиту ответа |
| не знает `json_schema` | просит просто JSON (`json_object`), схема остаётся в промпте |
| не знает формат ответа вовсе | JSON только по промпту |
| лимит ответа больше её предела | снижает до предела, который назвала модель |
| не знает `search_strategy` / настройки поиска | убирает их |
| не умеет искать (карточка с веб-поиском) | отвечает без поиска |

Каждая поправка пишется в лог сервера и в поле `ai.fixes` ответа.

**Повторы.** Перегрузку и сбой сервиса (429, 5xx, обрыв связи) повторяем
один раз через 3 с. Истёкший таймаут не повторяем: раньше SDK сам повторял
его дважды, и медленная модель держала запрос втрое дольше таймаута.

**Ошибки — по-русски и с названием модели.** Например: «Модель «X» не
ответила за 10 мин», «Запрос не поместился в окно контекста модели «X»
(предел — 98 304 токенов)», «Модель «X» не умеет искать в интернете — для
поиска источников выберите другую». Исходный текст провайдера — в логе.

## Настройки (.env, необязательные)

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `AI_THINKING` | `off` | `off` — выключить размышления, `on` — включить, `default` — не передавать, пусть решает модель |
| `QWEN_SEARCH_STRATEGY` | `max` | глубина поиска DashScope: `turbo` — быстрее и дешевле, `max` — больше источников, `default` — не передавать |

После правки `.env` — `pm2 restart all`: сервер перечитывает `.env` при запуске.

## Как посмотреть, что происходит

**Лог сервера** — по строке на каждый ответ модели:

```
[qwen] model=deepseek-v4-pro: ответ за 41.2 с, поправки: модель не выключает размышления — ограничиваю их бюджетом
```

**Поле `ai` в ответе** — видно во вкладке Network браузера: модель, время
(`ms`), поправки (`fixes`), объём размышлений (`reasoningChars`), токены
(`usage`).

**Проверка моделей** — каждая модель проходит настоящие маршруты сервера:

```bash
node scripts/check-models.js                          # все модели: поиск, карточка, шаг
node scripts/check-models.js --models qwen3.6-flash   # одна модель
node scripts/check-models.js --tasks graph            # построение графа целиком (долго)
```

Запросы настоящие и расходуют токены тарифа.

## Карточка узла

Промпт карточки описывает поля в виде «Поле: …», а сервер ждёт JSON. Чтобы
модели без принудительной схемы не отвечали текстом, к любому промпту (и к
правленому в интерфейсе) дописывается описание JSON-ответа. Если модель всё
же ответила текстом «Поле: значение» или забыла обёртку `productCard`,
сервер разбирает и это (`routes/fill-card/utils/card.js`).

Граф в запрос карточки уходит сжатым: названия узлов и связи плюс данные
выбранного узла. Раньше уходил весь граф со всеми источниками и описаниями —
на больших графах это не помещалось в окно контекста модели.
