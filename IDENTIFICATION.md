# Как продукт графа опознаётся и находится в реестре

Описание сквозное: от выгрузки ГИСП до узла на полотне у клиента. Собрано,
чтобы вернувшийся через полгода не восстанавливал картину по коммитам.

Числа в тексте — на 23 сентября 2026; проверить текущие можно командой
`node scripts/audit-products.js`.

---

## Задача, из которой всё выросло

**Одно вещество — один узел.**

Модель строит граф и называет узлы как придётся: «ИПБ», «Кумол»,
«Изопропилбензол» — это одно вещество под тремя именами. Пока сравнивались
подписи, объединение двух графов давало три узла вместо одного, а достройка
шага заводила дубликат рядом с существующим.

Вторая половина задачи: чтобы сказать «этот продукт в России производят» и
назвать код ОКПД2, надо найти его в реестре — а там он записан четвёртым
именем: «Изопропилбензол (ИПБ) марки Т».

## Два механизма, которые легко спутать

|  | Опознание | Поиск по реестру |
|---|---|---|
| Вопрос | «это какое вещество?» | «его производят в России?» |
| Отвечает | справочник синонимов | база ГИСП |
| Результат | канон → идентификатор узла | производители, ОКПД2, регион |
| Нужен ли реестр | нет | да |
| Точка входа | `POST /api/industry/identify` | `POST /api/industry/lookup` |

Узлы схлопываются в один, даже если вещества нет в ГИСП вовсе. Это важно:
192 продукта на живых графах справочник знает, а реестр — нет, и это
нормально. Реестр ПП №719 — про товарную продукцию; промежуточных веществ
цепочки в нём нет, их не продают.

## Слой 1. Реестр ГИСП

Выгрузка `ВЫГРУЗКА.xlsx` → SQLite через `scripts/import-gisp.js`.

```sql
meta          -- на какую дату выгрузка
products      -- 162 532 записи: name, name_norm, okpd2, tnved,
              --   producer, inn, region, reg_number, status, url
products_fts  -- fts5(name_stem, content='', tokenize='unicode61 …')
```

Два решения в схеме, которые не надо «чинить»:

- **`content=''`** — индекс без копии текста. Из него нужен только `rowid`,
  строки берём из `products`. На 162 тысячах записей это заметная разница в
  размере файла.
- **`name_stem`, а не `name`** — в индексе лежат **усечённые** слова. Иначе
  «бутаны» из графа не находили «бутан технический» из реестра.

Импорт собирает `<файл>.new` и переименовывает в конце: прерванный посреди
записи импорт не портит рабочую базу (проверено настоящим SIGTERM).

Место на диске импорт бережёт сам. `--stats` меряет будущий размер на пробной
базе в памяти — каждая 20-я строка выгрузки в той же схеме — и говорит,
хватит ли места. Постоянный множитель «текст → файл» на миллионе строк
ошибался на четверть, проба — на доли процента (641 МБ предсказано, 640,9
получилось; на названиях с уникальными артикулами — 725 и 723,7). Сам импорт
останавливается, если свободного места остаётся меньше 100 МБ: на том же
диске живёт база приложения в Docker. Сжатие (VACUUM) даёт около 3% и требует
двух размеров базы сверху — без места на него импорт его пропускает.

Коды ОКПД2 «из 26.51.53» («входит в группу») и «7.10.10» (класс 07 без нуля)
импорт приводит к обычному виду — иначе отбор по классам их терял.

В базе сейчас вся продукция из выгрузки — классы 01, 02, 05–08, 10, 11,
13–17, 19–32: 1 073 105 записей, 783 МБ (до 2026-10-01 было 162 532 записи
сырьевых классов). Не взяты отходы (38), здания и сооружения (41–42),
программы (58) и строки без кода. Какие классы в базе и из какого файла она
собрана — `node scripts/query-gisp.js` без аргументов.

**Вещество ищется только среди веществ и материалов** (`SUBSTANCE_CLASSES` в
`store.js`: 01, 02, 05–08, 10–12, 13.1, 16.1, 16.21, 17, 19–24, 35). Сельское
хозяйство и лес — это сырьё: «Кукуруза» справочника находит зерно из 01. У
текстиля и дерева — только материалы: пряжа и волокна, пиломатериалы, фанера и
плиты. Ткани, тюль, канаты и деревянные изделия — уже изделия: «Полиэфирсульфону»
доставался тюль «(100% PES)» — в текстиле PES это полиэфир. В изделиях название
вещества стоит материалом или комплектующим — «Генератор азота мембранный» (28)
у «Азота», «Аккумуляторная батарея с серной кислотой» (27) у «Серной кислоты», —
и отбор по месту слова такие записи пропускает. Ограничение стоит в самом
запросе, иначе сотни изделий вытеснили бы вещество из выдачи.

**Продукт, которого справочник не знает,** ищется сперва там же, среди
веществ и материалов. Не подтвердилось ничего — среди изделий, и строже:
запись засчитывается, только если продукт назван в ней с первого слова
(«Генератор азота мембранный» на графе машиностроения). Второе слово, скобка,
состав у изделия называют его материал, среду или начинку: на полном реестре
«Масла» без этого находили «Нож для масла» и теряли за ним моторные масла,
«Пар» — «Трубопровод обвязки (пар)», «Полиуретаны» — ткань «с эластаном
(полиуретаном)». Мягкие ступени («любое из слов») идут последними и по всему
реестру: подтверждения они не дают, нужны для разбора, а с отбором по классам
на миллионе записей втрое медленнее.

«Уголь» усекается целиком (`KEEP_WHOLE` в `normalize.js`): без мягкого знака
это «угол», и уголь подтверждался угловыми секциями кабельных лотков.

**Неатомарное поле.** В `okpd2` бывает несколько кодов сразу —
`"20.13.25.114, 20.13.25.119"`, `"20.16.30; 20.13.25"`. Поле разделяется при
чтении; сперва такие строки считались отсутствующими в классификаторе, и это
было неправдой (коммит `795aebb`).

**Коды записей.** Записи одного продукта стоят под разными кодами — заявитель
выбирает код сам. Карточке достаётся один (тот, что классификатор связывает с
веществом, а среди таких — самый частый), а все коды с числом записей
приходят списками `okpd2Codes` и `tnvedCodes`: по ним карточка раскрывает «у
остальных записей ещё кодов: n». Человек может поставить продукту другой код
— из этих или вписать свой; такой код живёт в узле графа
(`data.codeOverrides`), а название ему даёт `POST /api/industry/codes`
(`{ okpd2?, tnved? }` → формат, название по классификатору, `known` — есть
ли код в нём; реестр для этого не нужен).

## Слой 2. Справочник синонимов

Текстовый файл, строка на вещество. Первое имя — **канон**, он же
идентификатор; дальше написания; в комментарии номер CAS.

```
Изопропилбензол | Кумол | ИПБ | Cumene   # CAS 98-82-8
```

Делает две работы разом:

1. **Опознание.** `identify("Кумол")` → `Изопропилбензол`. Это и есть
   `productId` узла.
2. **Расширение поиска.** В реестре ищем не одним написанием, а всеми:
   «Изопропилбензол» не нашёлся — пробуем «Кумол».

Подписи со скобкой опознаются по половинам (`identifyParenthesized`):
«Изопропилбензол (ИПБ)» — обе половины известны и про одно вещество;
«Хлор (Cl2)», «Этиленгликоль (ЭГ)» — известна голова, а в скобке формула или
сокращение, то есть пересказ названия. И наоборот, обозначение впереди,
название в скобке: «BR (бутадиеновый каучук)», «PET (полиэтилентерефталат)».
Уточнение словами по-русски — «Полиэтилен (вторичный)» — не опознаётся:
это уже другой продукт.

Сейчас: **341 вещество, 924 написания, 225 номеров CAS**.

Почему файл, а не база: правится человеком, приезжает вместе с кодом (значит
одинаков на всех машинах), читается лениво и целиком влезает в память. Когда
переезжать в SQLite — записано в `TODO.md`.

### Строк в файлах больше, чем веществ

`439 строк = 341 вещество + 98 строк, влившихся в уже известные`

Строка не равна веществу. Wikidata дописывает синонимы к тому, что уже есть
в `synonyms.txt`, чаще под тем же главным именем — такая строка вливается в
известную запись. Из 84 влившихся 12 описывали вещество под **другим**
главным именем («Мочевина» → «Карбамид»); их показывает
`audit-products.js --merged`.

### Три источника

**1. Руками** — `reference/synonyms.txt`, 310 строк. Ходовые названия.
Минус: наполняется наугад относительно того, что реально встречается.

**2. Wikidata** — `scripts/fetch-wikidata-synonyms.js` →
`reference/synonyms-wikidata.txt`, 65 строк.

```
node scripts/fetch-wikidata-synonyms.js --missing-only --dry-run --all
```

— опросить только незнакомые справочнику названия с графов и показать ВСЕ
найденные записи (без `--all` — первые двенадцать). Без `--dry-run` при
`--missing-only` найденное **дописывается** к файлу по коду элемента
Wikidata; прежде файл переписывался одними новыми веществами, и собранное
раньше пропадало.

```
node scripts/fetch-wikidata-synonyms.js --missing-only --graph ТИТАН --no-cas --dry-run --all
```

- `--graph ТИТАН` — только названия с одного графа; граф ищется и по имени
  файла, и по названию, без учёта регистра. Так новый граф опрашивается за
  минуты, а не заново все шестьсот названий. Запись — тоже дописыванием.
  Тот же ключ понимает `audit-products.js`.
- `--no-cas` — спросить и про вещества справочника, у которых нет номера
  CAS (канон и написания без звёздочки). Решение — по веществу: если его
  написания привели к РАЗНЫМ номерам («Сульфат меди» и «Медный купорос» —
  безводная соль и пентагидрат), номер не предлагается, показываются оба.
  Номер, который уже стоит у другого вещества справочника, помечается
  «!!!». Файлы в этом режиме не трогаются: номер ложится в строку
  `synonyms.txt`, а за каждую её строку отвечает человек.

  Здесь же — и только здесь — засчитывается перенаправление Википедии:
  «Гексафторпропилен» ведёт на статью «Гексафторпропен», хотя в Wikidata
  такого синонима нет. Строка помечается «только по перенаправлению»:
  перенаправление бывает и на статью шире вещества («Водное стекло» →
  «Силикаты натрия»). В файл синонимов так не пишется — там нужно точное имя.

Два названия, ведущие перенаправлением на одну статью («Кумол» и «Кумен»
→ «Изопропилбензол»), получают её оба; раньше — только одно из них.
`--names` пишет дописыванием, как и опрос одного графа: полная перезапись
файла находками короткого списка стёрла бы остальное.

Нужен был не синоним, а **номер CAS**: единственный ходовой идентификатор
самого́ вещества. ОКПД2 и ТН ВЭД классифицируют товарные КАТЕГОРИИ, и под
одним кодом лежат разные продукты. Открытой базы CAS нет, Wikidata хранит
номер свойством `P231`, а рядом русские название и синонимы — то есть то же,
что мы писали руками, но с происхождением: у записи код элемента, который
можно открыть и проверить.

Три решения, которые стоили отладки:

- **Спрашиваем про свои продукты, а не качаем всё.** Запрос «все вещества с
  номером CAS» публичная точка не отдаёт — отваливается по таймауту.
- **Пачками через ru.wikipedia, остаток поштучно через Wikidata.** Поиск по
  одному упирался в ограничение частоты (429); лекарство — не частить, а
  спрашивать пачками. Пачка ограничена и счётом (50), и длиной адреса: русская
  буква занимает в адресе шесть знаков, и полсотни длинных названий получали
  «414 URI Too Long». Если адрес всё же вышел длинным, пачка делится пополам.
- **Вещество с одним именем в файл не идёт, но показывается.** Строка из
  одного имени ничего не схлопывает, зато номер CAS даёт продукту
  международный идентификатор в карточке. Такие сборщик печатает отдельным
  списком («С номером CAS, но без второго имени») — только тех, кому
  справочник номера не даёт, с пометкой, если имя там уже есть без номера или
  с другим. Годные переносятся в `synonyms.txt` руками, строкой
  «Имя   # CAS …»: при полном пересборе машина прицепила бы номер и к
  записи, которую человек понимал иначе.
- **Неоднозначные откладываем, а не угадываем.** Подошло несколько разных
  веществ — не выбираем. Угадав, мы слили бы в один узел разные вещества, и
  заметить это потом было бы нечем.

**3. Сам реестр** — `scripts/mine-gisp-synonyms.js`. В реестре 84 тысячи
названий, писанных производителями, и второе имя вещества у них сплошь и
рядом стоит в скобках сразу после первого:

```
Изопропилбензол (кумол) Марка А
Мел химически осажденный (карбонат кальция) по ГОСТ 8253-79
```

Скрипт **ничего не добавляет сам** — печатает кандидатов, решает человек.
Ошибочный синоним молча сливает два разных вещества в один узел.

Отсев подобран по живому выводу, и почти весь он — про товары, а не про
химию. Сырой список из реестра — 1352 пары, и в основном это размеры
конвертов, марки стали, МНН лекарств, «(марок А)», «(раствор)», унитазы из
полипропилена. Пара остаётся, если:

- хоть одна сторона похожа на химию — слово-класс («кислота», «хлорид»),
  формула из настоящих символов элементов, приставка номенклатуры;
- голова — не готовый препарат и не изделие («Средство дезинфицирующее»,
  «Клей», «Трубы … из полиэтилена»): после них в скобке состав или материал;
- нигде нет торговой марки (®, ™, имя в кавычках);
- скобка — не форма, не сорт, не чистота и не размер;
- одна сторона не оказалась известным именем с довеском: «Пакет ПНД
  (полиэтилен низкого давления)» — ПНД справочник знает, нового только
  «пакет».

На живом реестре из 1352 пар первого прогона кандидатами остаётся около
сотни, и ни одна из верных пар, отобранных вручную, не теряется. Правила разбора скобки — `scripts/lib/paren-pairs.js`,
общие с добытчиком по своим графам (`scripts/mine-graph-synonyms.js`).

### Стоп-лист

`reference/synonyms-stop.txt` — применяется **при чтении** и только к
собранным машиной файлам. Wikidata щедра на «синонимы», которые синонимами
не являются: «Фениловый водород» (книжная архаика), «Гликоль» (класс, а не
вещество), «Раундап» (торговая марка гербицида). Сейчас выбрасывается 13
написаний.

### Пометка `*` — «только для опознания»

Сокращение бывает полезно для опознания и ядовито для поиска: «ДЭГ» — это
диэтиленгликоль, но в реестре ДЭГ-1 — марка эпоксидной смолы; «R22» — хладон,
но в реестре это типоразмер шины.

```
Диэтиленгликоль | *ДЭГ   # CAS 111-46-6
```

Помеченное написание опознаёт узел и участвует в слиянии, но из поиска по
реестру исключается. Сейчас помечено 18 написаний. Смотреть кандидатов:
`audit-products.js --abbr` — знак `!` там означает, что запись проходит вето
и дошла бы до заказчика.

## Слой 3. Нормализация названий

`routes/industry/utils/normalize.js`, и **та же логика продублирована на
клиенте** — `src/utils/normalizeProductName.ts`. Это не случайность:
справочник обязан отвечать одинаково на оба написания «Бисфенол A», а клиент
сравнивает подписи узлов при объединении. Разойдутся — узлы перестанут
схлопываться.

```
«Бутан-1,2-дикарбоновая КИСЛОТА, техническая»
  ↓ NFC, ё→е, дефисы и неразрывные пробелы → пробел, нижний регистр
  ↓ foldLookalikes: латинские двойники → кириллица
  ↓ words(): выброс стоп-слов (и, в, для, с, по…)
  ↓ stemWord(): усечение окончаний
«бутан 1,2 дикарбонов кислот техническ»
  ↓ coreWords(): выброс слов, которые есть почти у всего
«бутан 1,2 дикарбонов кислот»
```

**Ловушки, на которых обожглись:**

- `\b` в JavaScript **не работает с кириллицей**. Наступали трижды.
- `words()` выбрасывает «А» и «С» как стоп-слова — а в «Аммиак марки А» и
  «Кислота серная марки С» эти буквы различают продукты. Есть места, где
  `words()` применять нельзя.
- `coreWords()` роняет токены короче трёх знаков — вместе с ними исчезают
  «п-», «(NH4)» и прочие различители изомеров. Ступень, потерявшая такое
  слово, помечена `lossy` и по чужим написаниям не применяется.
- `GENERIC_WORDS` пополнять **осторожно**: слово оттуда считается не несущим
  различия. «Вторичный» туда класть нельзя — вторичный полиэтилен слился бы
  с первичным сырьём. По той же причине там нет «нового».
- Элементы на «-ий» усекаются **по списку** (`ELEMENT_NOUNS`): общее правило
  давало «натрий» → «натр», но «натрия» → «натри», и «Хлорид кальция» не
  находил «Кальций хлорид». Теперь в именительном отрезается одно «й», основа
  у падежей общая. Так же `FLEETING_VOWEL`: «марганец» — «марганца». Списком,
  а не по окончанию: у прилагательных на «-ий» («технический») основа как
  раз без «и». Германия, индия, франция и радия в списке нет — их родительный
  падеж совпал бы с Германией, Индией, Францией и «ради».
- Старые названия классов солей и окислов сводятся к новым **по основе**
  (`CLASS_STEMS`): «хлористый» → «хлорид», «углекислый» → «карбонат»,
  «сернокислый» → «сульфат», «азотнокислый» → «нитрат», «окись» → «оксид»,
  «перекись» → «пероксид». «Хлорид натрия» находит «Натрий хлористый
  пищевой», а «Кальций углекислый (карбонат кальция)» больше не отсекается
  как «соединение рядом». «Сернистый» не сводится: это и сульфид («натрий
  сернистый»), и сернистый газ; «закись» — тоже: закись азота и оксид азота
  разные вещества.
- Слова, которые только похожи на словоформу, не усекаются вовсе
  (`KEEP_WHOLE`): «Нафтам» — имя продукта, а общее правило срезало «-ам»
  как окончание дательного падежа, и «Нафтам 04» подтверждал «Нафту».
- **Индекс реестра этой правкой не перестраивался.** В нём лежат основы,
  усечённые прежним правилом («натрий» → «натр»), и запрос к нему спрашивает
  обе основы сразу (`LEGACY_STEMS`, `ftsTerm`). Решает не индекс, а сверка
  записи с запросом — она идёт новым усечением. Поэтому ни пересобирать базу,
  ни менять порядок снятия снимков не нужно: старый код читает тот же индекс.

## Слой 4. Поиск по реестру

`routes/industry/utils/store.js`.

### Лестница запросов

```
exact       точное совпадение названия
all-words   все значимые слова         ← строгая
core-words  только ядро слов           ← строгая
partial     любое из слов              ← мягкая
prefix      по началу слова            ← мягкая
```

Три правила, каждое куплено ошибкой:

1. **Ступени снаружи, написания внутри.** Иначе мягкое совпадение по первому
   написанию побеждало строгое по второму.
2. **По чужим написаниям — только строгие ступени и не `lossy`.**
   «Незамерзайка» знает синоним «стеклоомывающая жидкость», и мягкая ступень
   по нему цеплялась за тормозную.
3. **Мягкие ступени не считаются находкой.** На 662 продуктах так
   «находилось» 327 из 455, и это был мусор: «Синтез-газ» → «Заглушка ПЭ 100
   — ГАЗ». Такие совпадения уходят в поле `weak`.
4. **Ответ — первая попытка с ПОДТВЕРЖДЁННЫМИ записями, а не с любыми.**
   Раньше лестница обрывалась на первой находке, и вето уже потом могло
   отклонить её целиком — вещество выходило ненайденным, хотя следующее
   написание нашло бы его. «Карбамидно-аммиачная смесь» цеплялась за две
   записи с рубрикой впереди («Удобрения жидкие минеральные: …»), вето их
   отклоняло, и до «КАС» с пятью записями дело не доходило. Правило только
   добавляет найденное: первая подтверждённая попытка и раньше была первой.

5. **Записи собираются по ВСЕМ написаниям уровня, а не по первому
   сработавшему.** Раньше ответом были записи одной попытки: «Дихлорметан»
   находил свою запись и до «Метилен хлористый технический» не доходил,
   «Карбамидоформальдегидный концентрат» находил одну точную запись и не видел
   пяти «Концентрат карбамидоформальдегидный (КФК-85)». Уровней два строгих:
   «точно» вместе со «всеми словами» (точно названная запись и так содержит
   все слова) и ниже — «значимые слова»; ко второму спускаемся, только если на
   первом не подтвердилось ничего. Каждое написание проверяется отбором по
   себе самому, а запись, найденная двумя написаниями, считается один раз.
   Правило только добавляет: записи первой подтвердившейся попытки остаются в
   ответе все.

Попытка отсеять мусор порогом редкости слова провалилась: верное и ложное по
редкости **перекрываются** («хладон» — 72 записи и попадание верное, «легк» —
61 и мусор). Одной границы между ними не существует.

### Вето — `confirms()`

Найти мало, совпадение надо признать. Правило подобрано замером на 128
подтверждениях: разделяет не доля покрытия, а **место** — из 127
подтверждений 89 совпали первым же словом записи, и все верные, кроме одного.

Пять оснований принять; запреты сильнее их всех:

| Запрет | Что режет |
|---|---|
| `foreignClass` | «Азот» ← «Закись азота» — запись про соединение. Сюда же «кислый» рядом с совпавшим: «Карбонат натрия» ← «Натрий углекислый кислый» — это пищевая сода |
| `onlyClass` | «Эфиры ЖК» ← любой сложный эфир — совпало одно имя класса |
| `supplyForm` | «Янтарная кислота» ← «Стандарт-титры…» — мерный реактив |
| скобка | засчитывается синонимом, только если запрос покрыл **целую** альтернативу внутри скобки |
| два слова | засчитываются, только если стоят **рядом**: «Триоксид молибдена» ← «Порошок молибдена, изготовленный … восстановления триоксида молибдена» — «молибдена» вторым словом, «триоксида» в хвосте, где названо сырьё |
| `madeOf` | «Политетрафторэтилен» ← «Стержни из фторопласта-4» — «из» прямо перед веществом: изделие из него |
| `productBefore` | «Оксид цинка» ← «Гуашь "Белила цинковые"», «Изопропанол» ← «Средство дезинфицирующее ОЗАЛИЗ (изопропанол)», «Полиэтилен низкого давления» ← «Пакет ПНД (полиэтилен низкого давления) для мусора» и «Перчатки из полимерной пленки (полиэтилен низкого давления)», «Перекись водорода» ← «Добавка на основе пероксида водорода» — перед веществом изделие или продукт, который его содержит: средство, гуашь, среда, листы, пакет, мешок, перчатки, посуда и тара (чаша, стакан, ёмкость, канистра, флакон — «Чаша PP (полипропилен) BP330»), «на основе». Уступает препарату с дозировкой в скобке — см. ниже |
| `otherIsomer` | «Ксилол» (смесь изомеров) ← «О-Ксилол (1,2-диметилбензол) химически чистый», «п-Ксилол» — перед совпавшим словом приставка положения (о-, м-, п-, орто-, мета-, пара-, цифры «1,2-»), и справочник знает такой изомер ОТДЕЛЬНЫМ веществом, а спрашивали другое. Решает справочник, а не приставка: изомер, которого он отдельно не знает, запрос без приставки находит по-прежнему; запрос, которого он не знает, не судится вовсе. Обратный случай — спросили изомер («м-Ксилол»), а в записи то же слово без приставки («Ксилол нефтяной»), и справочник знает голое слово другим веществом (смесью изомеров). Номер после слова («Бутандиол-1,4») считается той же приставкой |
| `otherElement` | «Нитрат аммония» ← «Аммоний кальций нитрат», «Нитрат кальция» ← «Калий кальций нитрат», «Карбонат кальция» ← «Доломит (карбонат кальция и магния)» — рядом с элементом или словом-классом стоит ДРУГОЙ элемент, которого в запросе нет: двойная соль или смесь. Соседство проверяется только между частями химического названия: в «Полевой шпат (калий натрий алюмосиликат)» калий описывает состав шпата |
| `elementCompound` | «Натрий» ← «Натрия гипохлорит марки А», «Магний» ← «Магния стеарат», «Калий» ← «Кали едкое» — спросили сам элемент, а в записи он только в косвенном падеже, то есть в имени соединения. Сам элемент реестр называет в именительном: «Натрий металлический». Цена: «Порошок магния» по «Магнию» тоже не находится — как не находился и до общей основы падежей |
| число при слове | «Сополимер этилена с тетрафторэтиленом» (он же «Фторопласт-40») ← «фторопласт-ТМ моделей ПН25, ПН 40, Ф-4ТМ» — число, приписанное в запросе к слову через дефис, — марка или место заместителя, и совпадает, только если в записи стоит вплотную к тому же слову: до или после, одно или списком. «Пропанол-2» = «2-Пропанол», «Бутандиол-1,4» = «1,4-Бутандиол», «Фторопласт-40» = «Фторопласт Ф-40». Число через пробел («Соляная кислота 36%») — концентрация, её место не проверяется |
| сложное прилагательное | «Аммиачная селитра» ← «Селитра известково-аммиачная» — другое удобрение. Сложное слово через дефис совпадает только целиком: обе половины есть в запросе — два слова, нет хотя бы одной — склеиваются в одно и не совпадают ни с чем. «Изобутилен» ← «Бутилкаучук (изобутилен-изопреновый каучук)» отсекается тем же правилом. Приставки номенклатуры — «цис-», «транс-», «трет-», «изо-», «орто-» и т. п. — не половина сочетания: «цис-изопреновый» остаётся изопреновым (`NOMENCLATURE_PREFIXES`) |

Число при слове и сложное прилагательное держатся на одном правиле: **строгая
ступень требует у записи всех слов, которые спросила у индекса** (`required`
у попытки, `incomplete` в разборе). Индекс видит слова по отдельности и
находит «40» где угодно, а «аммиачную» — и внутри «известково-аммиачной»;
сверка строже. Если она не признала в записи хоть одно требуемое слово, это
отказ с названной причиной — даже когда соперников у записи нет и сравнивать
её не с чем. Записи, отсеянные сравнением числа совпавших слов, тоже попадают
в разбор с причиной, поэтому снимок пишет «число «40» не при своём слове», а
не «больше не находится поиском».

Итог на живых данных: «Азот» был 15 производителей (с закисью, оксидами и
мочевиной), стал 4. Подтверждений 128 → 104, все 24 отброшенных проверены
поимённо.

**Препарат и лекарство — свидетельства второго сорта.** Вещество в них есть,
но продаётся другой товар. Засчитываются они, только если самого вещества в
реестре нет (решение заказчика, сентябрь 2026):

- препарат — вещество названо в первой скобке с дозировкой: «ТОРНАДО, ВР
  (360 г/л глифосата к-ты)», «Средство антибактериальное (на основе
  изопропилового спирта 60%)»;
- препарат, названный по самому веществу, — «Сера 400, КС (фунгицид)»,
  «Диметоат 400, КЭ». Признак — код препаративной формы после запятой (КЭ,
  КС, ВР, СП, ВДГ… — как в каталоге пестицидов, прописными; однобуквенных
  и двусмысленных вроде «ВС» — высший сорт — нет) или слово-назначение в
  именительном падеже: «фунгицид», «гербицид», «инсектицид». «Сера для
  производства фунгицидов» — это сама сера; «десиканта» и «протравителя» в
  списке нет — это и осушитель, и протрава для дерева. Раньше такая запись проходила
  первым словом как само вещество: «Сера» и «Элементная сера» получали
  производителя фунгицида, а у «Диметоата» препарат «Диметоат 400, КЭ»
  отнимал право у «Би-58 Новый, КЭ (400 г/л диметоата)»;
- мочевинный раствор для дизелей — «AUS 32», «AdBlue» в названии
  («Мочевина восстановитель оксидов азота AUS 32»). Это товар из карбамида, а
  не карбамид; решение заказчика — считать как препарат. «Карбамид для DEF»
  (сырьё для такого раствора) остаётся карбамидом;
- лекарство или медизделие — слова «инфузий», «инъекций», «лекарственных»,
  «стерильный», «физиологический», «изотонический», «РЗН» в названии. Код
  ОКПД2 21.20 признаком не служит: под ним зарегистрирован и медицинский
  кислород, а это сам кислород, не лекарство с ним.

Глифосат находится через «ТОРНАДО»: самого глифосата в реестре нет. У
хлорида натрия растворы для инфузий не засчитываются: есть его собственная
запись. Если спрашивают о самом лекарстве («Физиологический раствор», «Вода
для инъекций»), лекарственные записи — не второй сорт, а ровно то, что искали.
Так же с препаратом: узел «Сера 400, КС» или «AdBlue» спрашивает о нём
самом, и пометки «в составе препарата» у такого ответа нет — узел и есть
препарат. То же у узла-класса: «Средства защиты растений», «Пестициды»,
«Гербициды» спрашивают о препаратах вообще (класс узнаётся по основам, в
любом числе и падеже). Основание у засчитанного препарата пишется с пометкой —
«препарат: первое слово», — чтобы в снимке он не выглядел находкой вещества.

Снимок записывает пометку `viaFormulation` и показывает её смену отдельным
разделом «ПОМЕТКА «В СОСТАВЕ ПРЕПАРАТА»»: записи при этом могут остаться
прежними — у «Серы» «Сера 400, КС» была и остаётся единственной, — а смысл
находки другой.

Поймано снимком: у «Хлорида натрия» 22 записи из 24 были лекарствами, и код
ОКПД2 выходил «Растворы плазмозамещающие и перфузионные».

**Код ОКПД2** — самый частый среди подтверждённых записей, причём сперва
среди кодов, чьё название говорит о веществе. Ничью решает позиция, названная
ровно веществом: у «Бутана» по записи под «Бутан» и под «Бутан сжиженный», и
побеждает «Бутан».

Потом код **уточняется по классификатору**: заявители ставят код категории, а
под ним бывает позиция самого вещества. У «Капролактама» записи стоят под
20.14.52.110 «Соединения гетероциклические…», а в классификаторе под ней есть
20.14.52.111 «Капролактам» — карточка показывает её, а код записей отдаёт
полем `okpd2Registry` («уточнён по классификатору; в реестре — …»). Берётся
только позиция, названная ровно веществом, и только если она одна: «Бензол»
под «Бензолами» не уточняется (каменноугольный, сланцевый, нефтяной), а
совпадение по части слов не годится — «Азот» нашёл бы «Закись азота».
Уточнение видно в снимке строкой «код переехал».

**Код ТН ВЭД** — самый частый у подтверждённых записей. Нет его у записей
(или записи нет вовсе) — карточка показывает позицию классификатора по
названию вещества, поле `tnvedCategory`, с пометкой «по классификатору»
(`tnvedByName.js`, группы 28–29, правила сверки — в TODO.md). Сколько
продуктов графов получают код каким путём — `node scripts/codes-coverage.js`.

### Подписи, которые не называют вещество

Реестру такое название не задаётся вовсе; ответ помечается `placeholder`, и
карточка говорит «продукт ещё не назван», а не «записи нет» — мы не искали.

Два вида, оба пришли с живых графов:

- **заготовки интерфейса** — `PLACEHOLDER_NAMES` в `store.js`: «Новый
  продукт», «Новое преобразование», «Новый узел», «Без названия». Сверяются
  **целиком**: «Новый продукт» — заготовка, а «Полиэтилен новый» — возможное
  название, и вырезать из него слово нельзя;
- **одни определения без существительного** — `isQualifierOnly` в
  `normalize.js`: «Новый», «Серная». Вещества называются существительными.

Зачем оба: ступень «значимые слова» сводит «Новый продукт» к одному слову
«новый» («продукт» выброшен как общее), а в реестре полно торговых имён с
ним — «Жироудалитель „Новый Элемент“». Слово совпадает вторым, покрывает
треть записи, и вето такое пропускает. Правило вето при этом верное — спросили
не о том.

**Ловушка при пополнении `QUALIFIER_END`:** окончания «-ий» там нет намеренно.
На него кончаются названия элементов — магний, кремний, алюминий, литий,
силиций, — и правило съело бы полтаблицы Менделеева. Перед включением
замерено: из 788 написаний справочника под правило не подпадает ни одно.

## Слой 5. Идентификаторы: сервер ↔ клиент

### Запрос

```
POST /api/industry/identify
  { "products": ["ИПБ", "Кумол", "Кубовый остаток колонны К-102"] }

  { "success": true, "ready": true, "results": {
      "ИПБ":   { "id": "Изопропилбензол", "canon": "Изопропилбензол",
                 "exact": false, "cas": "98-82-8" },
      "Кумол": { "id": "Изопропилбензол", … },
      "Кубовый остаток колонны К-102": null } }
```

Неопознанные возвращаются как `null`, а не пропускаются: клиенту важно
отличать «справочник не знает» от «не спрашивали».

### Клиент — `src/utils/resolveProductIds.ts`

- собирает подписи узлов **без** идентификатора (заданный человеком или
  взятый из ТН ВЭД трогать нельзя — он точнее);
- спрашивает пачкой по 500;
- кладёт в `node.data.productId` + `productIdSource: "dictionary"`;
- **кэширует ответы на весь сеанс** — справочник не меняется, пока работает
  сервер;
- **сервер молчит — не беда**: объединение и сборка шага продолжают работать,
  схлопывая по названиям, как до справочника.

Срабатывает в трёх местах: граф построен с нуля (эффект в `Flow.tsx`), шаг
пришёл от модели (`identifyStepProducts`), объединение графов
(`mergeProductGraph`).

### Когда клиент спрашивает сервер

Замерено счётчиком запросов в браузере, а не выведено из кода.

| Что делает человек | `/identify` | `/lookup` |
|---|---|---|
| Открыл граф | 1 запрос, все продукты пачкой | 1 запрос, все продукты пачкой |
| Добавил продукт руками | 1 запрос на новую подпись | 1 запрос на новую подпись |
| Переименовал узел | 1 запрос на новое имя | 1 запрос на новое имя |
| Построил шаг | внутри санка, до укладки на полотно | потом, общим ходом полотна |
| Объединил графы | по разу на каждую сторону | потом, общим ходом полотна |
| Повторил то же самое | 0 — кэш сеанса | 0 — таблица результатов |

Два правила, которые видно только по замеру:

- **`/identify` не зависит от тумблера «Промышленные данные».** Слой выключен —
  реестр не спрашиваем, а справочник спрашиваем всё равно: идентификатор нужен
  для слияния узлов и без реестра. Включили слой обратно — `/lookup` уходит
  за тем, чего ещё не спрашивали.
- **Спрашивается только новое.** Оба пути держат свой кэш на сеанс:
  `resolveProductIds` — карту ответов справочника, `industrySlice` — таблицу
  результатов по нормализованному имени. Повторное объединение тех же графов
  не поднимает ни одного запроса.

Шаг опознаётся **внутри санка** (`identifyStepProducts` в `step-chain-api.ts`),
до того как ляжет на полотно: кладётся он синхронно, в редьюсере, и спросить
сервер там будет уже негде. Объединение — в `useMergeGraph`, по разу на
каждую сторону: опознать одну сторону бессмысленно, «ИПБ» сойдётся с
«Изопропилбензолом», только если канон есть у обоих.

**Переименование снимает идентификатор из справочника.** Он выведен из
прежнего имени, и после правки подписи врёт: узел, переименованный из
«Кумола» в «Толуол», оставался «Изопропилбензолом» и при объединении сливался
с ним. Идентификатор, заданный человеком вручную, переименование не трогает —
он не функция от имени.

### Когда два узла — один продукт

`src/utils/productIdentity.ts`. Правило одно, у него две стороны:

- совпали идентификаторы → одно вещество, как бы ни были подписаны;
- идентификатора нет хотя бы у одного → сравниваем названия, как раньше (у
  половины графов кодов нет и не будет);
- **запрет**: обе стороны назвали идентификатор и они разные → совпадение
  названий уже ничего не значит. Два разных «Масла» остаются разными.

Тонкость: идентификатор из справочника — это каноническое **название**,
поэтому его сравнивают и с подписями. Так узел «ИПБ» с идентификатором
узнаёт узел «Изопропилбензол», которому идентификатор ещё не проставили. Для
CAS так нельзя: узел, подписанный «98-82-8», сошёлся бы с веществом, у
которого это код.

## Чего здесь намеренно НЕТ

**Атомизации названий реестра.** Названия не разбираются на поля при
хранении (вещество / марка / ГОСТ / форма). Разбор идёт **в момент запроса**:
`keepBestOverlap` раскладывает название на слова и смотрит, чем совпавшее
слово приходится записи. Размен осознанный:

| Разобрать при хранении | Разбирать при запросе (наш путь) |
|---|---|
| быстрее и точнее там, где разбор верен | медленнее, зато исходник цел |
| ошибка разбора оседает в базе навсегда и невидимо | ошибка правила видна и чинится одной правкой |
| правило поменялось → полный переимпорт | правило поменялось → все прошлые ответы стали лучше сразу |

`confirms()` правился десятки раз. При атомизации каждая правка стоила бы
переимпорта, а старые ошибки жили бы в базе до него. Если когда-нибудь
двигаться в сторону атомизации — начинать с поля `okpd2`, где несколько
кодов лежат в одной ячейке: вот там атомарность нужна по существу.

**Нормальных форм в таблице `products`.** Производитель, регион и ОКПД2
лежат текстом в строке, а не ссылками на справочники; производитель
повторяется в сотне строк. Это нарушает 3НФ — и правильно: база только
читается и целиком пересобирается при каждом импорте. Аномалий обновления,
ради которых 3НФ и придумана, здесь возникнуть не может, а джойны на каждый
запрос стоили бы скорости.

## Как проверять изменения

Правила отбора менялись десятки раз, и единственный способ не сломать
найденное — **снимок до и после**: что реестр отвечает на каждое наше
название (справочник и продукты с графов) старым кодом и новым.

На сервере это одна команда сразу после `git pull`:

```
bash scripts/snapshot-check.sh ORIG_HEAD
```

`ORIG_HEAD` — то, что стояло до `git pull`. Можно назвать и коммит:
`bash scripts/snapshot-check.sh 37dce42`. Скрипт достаёт старый код во
временную папку, снимает им снимок, снимает второй текущим и сравнивает;
рабочую папку, базу и запущенный сервер не трогает.

То же руками — если снимок «до» сняли, ещё не подтянув правку:

```
node scripts/lookup-snapshot.js --out before.json
# … правка или git pull …
node scripts/lookup-snapshot.js --out after.json
node scripts/lookup-snapshot.js before.json after.json
```

Четыре кучки: ПРОПАЛО (выход 1 — это регрессия), ЗАПИСИ ИЗМЕНИЛИСЬ, ДРУГОЙ
КОД ОКПД2, НАШЛОСЬ ВПЕРВЫЕ. Пятая, «перестало считаться названием вещества»,
— не потеря: это подписи вроде «Новый продукт», по которым реестр не
спрашивают намеренно. Шестая, «НОВЫЕ НАЗВАНИЯ», — пополнение справочника:
сравнивать их не с чем, но что они нашли, читают так же глазами.
Ни одна правка правил не принималась без этого.

**В снимке — все записи, с повторами и основанием.** Каждая подтверждённая
запись, а не одна на производителя, и при ней основание отбора: чем
подтвердилась («первое слово», «второе имя в скобках») или каким запретом
отброшена («изделие «из» вещества»). «×N» в отчёте — столько одинаковых
записей. Ушедшие записи идут группами:

- «отбор: …» — поиск запись находит, но её снимает названный запрет;
- «больше не находится поиском» — поиск перестал её доставать: написание
  получило звёздочку или ответ собрался на другой ступени.

Ушедшие печатаются всегда целиком, пришедшие — по 10 названий на группу;
все — ключом `--full`: `bash scripts/snapshot-check.sh ORIG_HEAD --full`.
Раньше снимок хранил по одной записи на производителя и без повторов, и у
«Изопропанола», потерявшего 65 записей из 80, в отчёте стояла одна строка
«−».

**Новое написание может СУЗИТЬ выдачу.** Точное совпадение любым написанием
обрывает поиск на первой ступени. Когда в реестре нашлась запись, названная
ровно «натрий гидроксид», гидроксид натрия стал находить 1 запись вместо 8:
до ступени «все слова» поиск больше не доходил. Снимок показывает это в
кучке «ЗАПИСИ ИЗМЕНИЛИСЬ», а лечится звёздочкой у такого написания.

Разобраться, почему конкретное вещество не находится:

```
node scripts/why-missing.js "Бензол" --all
```

Три кучки: строгое совпадение отброшено вето / только отдалённое сходство /
реестр молчит.
