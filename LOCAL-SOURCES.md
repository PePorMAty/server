# Локальная база источников

Источники для построения шагов теперь бывают трёх видов:

| Вид | Откуда | Как попадает в базу |
|---|---|---|
| **PDF** | документы заказчика | загружает человек: кнопкой в интерфейсе или скриптом на сервере |
| **Веб, сохранённые** | найденное моделью раньше | само: каждый успешный поиск через модель дописывает найденное |
| **Веб, новые** | поиск через модель сейчас | «добрать» в окне построения шага |

У PDF приоритет: в обобщение шага они идут первыми. Всего в обобщение
уходит до 10 источников (раньше — 5).

## Где лежит

`data/local-sources/` (в git не попадает, как и реестр ГИСП):

- `sources.sqlite` — документы, фрагменты текста с индексом, сохранённые
  веб-источники;
- `files/<sha256>.pdf` — сами PDF: из карточки их открывают на нужной
  странице.

Каталог можно переопределить переменной `LOCAL_SOURCES_DIR`.

## Как PDF становится источником

1. Текст достаём PDF.js (тот же, что в Firefox; пакет `unpdf`) — без внешних
   программ. Перенос слова по слогам («произ-водство») склеивается.
2. Текст режем на фрагменты по абзацам, до ~1500 знаков, в пределах
   страницы: номер страницы — ссылка, по которой человек проверит, откуда
   текст.
3. Фрагменты индексируются по основам слов — тем же усечением, что у реестра
   ГИСП: «пропилена», «пропиленом» и «пропилен» — одно слово.

Сканы (страницы без текста) не распознаются: при загрузке сервер говорит,
сколько таких страниц; PDF целиком из сканов не принимается.

## Как продукт находит свои PDF

Как опознание продуктов: по **всем написаниям из справочника**. У
«Изопропилбензола» найдутся и «кумол», и «ИПБ». Написания со звёздочкой
(только для опознания — «ММА», «ПНГ») в поиск не идут: они приносят чужие
вещества.

- Название из нескольких слов ищется словами **рядом и в любом порядке**:
  «серная кислота» найдёт и «кислоты серной», и «серной и азотной кислоты».
- Короткие слова, которые усечение не трогает («сера», «газ»), ищутся со
  своими падежами: «сера» найдёт «серу» и «серы».

Продукту отдаём до 5 документов — где он упоминается чаще; текст источника —
два лучших фрагмента документа.

## Сохранённые веб-источники

Каждый успешный поиск через модель (`/gpt/step/sources`, `/gpt/sources`)
записывает найденное в базу — по продукту и направлению (вверх/вниз).
Продукт узнаётся по справочнику: источники, найденные для «ИПБ», видны у
«Кумола» в любом графе. Повторно найденный адрес обновляется, не задваивается.

## HTTP

| Запрос | Что делает |
|---|---|
| `GET /api/local-sources/documents` | список PDF |
| `POST /api/local-sources/documents` | загрузить PDF: тело — сам файл (`Content-Type: application/pdf`), имя — в заголовке `X-File-Name` (encodeURIComponent) |
| `DELETE /api/local-sources/documents/:id` | удалить документ |
| `GET /api/local-sources/documents/:id/file` | открыть PDF (`#page=N` — на странице) |
| `POST /api/local-sources/lookup` | `{ products: [...] }` → у каждого: `{ local, web: { up, down } }` |
| `POST /api/local-sources/for-product` | `{ product, direction }` → `{ local: [...], web: [...] }` |

Источники отдаются в том же виде, что и найденные моделью (`title`, `url`,
`technology_description`…), плюс `origin: "local" | "web"`. У PDF `url` —
путь относительно API (`local-sources/documents/12/file#page=3`): клиент
дописывает к нему свой адрес сервера.

Номер удалённого документа новому не достаётся — ссылка в сохранённом графе
не откроет чужой PDF.

## Скрипт

```bash
node scripts/import-pdf.js ~/pdf/                  # все PDF из папки (и подпапок)
node scripts/import-pdf.js отчёт.pdf статья.pdf    # отдельные файлы
node scripts/import-pdf.js --list                  # что в базе
node scripts/import-pdf.js --find "Пропилен"       # что база отдаст продукту
node scripts/import-pdf.js --delete 12             # удалить документ
```

Тот же файл второй раз не добавляется (сравнение по содержимому). Сервер
перезапускать не нужно: загруженное видно сразу.

## Установка на сервере

После `git pull` один раз: `npm install` — появился пакет `unpdf`.

Если перед сервером стоит nginx, проверьте `client_max_body_size`: по
умолчанию он пропускает запросы до 1 МБ, и загрузка PDF побольше
оборвётся ответом 413 ещё до сервера. Сервер принимает PDF до 100 МБ:

```nginx
client_max_body_size 100m;
```
